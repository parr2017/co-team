## 代码审查清单（逐项核对后在报告中给出结论）

### 正确性
- [ ] 逻辑是否与需求一致？边界条件（空输入、极值、并发）是否处理？
- [ ] 错误处理是否完整（try/catch、失败分支、超时）？

### 可维护性
- [ ] 命名是否达意？函数是否单一职责？
- [ ] 是否复用了既有工具函数而不是重复造轮子？

### 安全
- [ ] 用户输入是否校验？路径/SQL/命令是否存在注入面？
- [ ] 密钥/敏感信息是否硬编码？

### 测试
- [ ] 关键路径是否有测试覆盖？失败分支是否测到？
- [ ] 测试是否可重复运行（无固定时间/随机依赖）？

## 报告格式要求
发现的问题按 P0（阻断）/P1（应修）/P2（建议）分级，每条给出文件与行号、问题描述、修复建议。
