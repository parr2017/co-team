# 飞书接入·功能树与交互设计规格（2026-09-26，rev2）

> 定位：飞书接入的交互规格（v2 已实施，本文即实现依据）。分类原则——**飞书承接"等你拍板的"和"告诉你结果的"，H5 承载"需要你操作的"**。
> 标记：[v1] 已上线 · [v2] 本批实施（2026-09-26 已落地） · [观察] 暂不排期。

---

## 1. 功能树

```
Co-Team 飞书机器人
├─ 私聊窗口（三态互斥：task / convo / oc，/exit 永远回 task）
│  ├─ 通用指令（任何模式）：/help  /status  /exit  /reset
│  ├─ task 任务模式（默认）
│  │   ├─ 自由文本 → 建任务（需已 /project 选项目）[v1]
│  │   ├─ /project · /agent · /tasks · /queue [v1]
│  │   ├─ /metrics（成本/成功率摘要）· /task <id>（进度卡）[v2]
│  ├─ convo 会话模式（/convo 进入并自动列出已有对话）
│  │   ├─ /list 会话列表 · /new [标题] · /switch <序号|id> [v2]
│  │   ├─ 自由文本 → 注入会话（未绑定对话时自动新建）[v2]
│  │   └─ 会话审批/提问 → 决策卡 [v2]
│  └─ oc OpenCode 模式（/oc 进入并自动绑定活动会话）
│      ├─ /list 实例+会话列表 · /new [标题] · /switch <序号> [v2]
│      ├─ /model · /agent（裸命令列选项，带参切换）[v2]
│      ├─ /stop 中止 · 自由文本 → 发 prompt [v2]
├─ 群聊（只收 @消息，永远 task 模式）→ 建任务 [v1]
└─ 被动推送（无需指令）
   ├─ 任务生命周期卡 [v1] · 决策卡 [v1 节点/命令，其余 v2]
   ├─ ★ oc 全局监控 [v2]：监控【所有实例的所有会话】——
   │    · 会话完成 → 推结果通知（不限绑定会话）
   │    · 出现待确认权限 / 提问 → 推审批卡（跨实例聚合，30s 扫描 + 事件驱动）
   ├─ convo / oc 终稿推送（发 prompt 即回执，完成即推送，关飞书也推）[v2]
   └─ 中途插话：回复任务卡即注入 [v2]
```

**不在飞书做**：计划评审 DAG 编辑、agent/模型池/全局权限/MCP 设置、指标图表、讨论全文流、H5 嵌入、delta 级流式、语音、会话文件上传。

## 2. 指令设计总则：裸命令看选项，带参数才执行

所有"选择类"命令统一一个模式——**不带参数 = 列出编号选项（当前项打标）；带序号或名称 = 执行切换**。序号来自最近一次列表（session 缓存，被新列表覆盖）。

| 命令 | 裸命令（看） | 带参数（做） |
|---|---|---|
| /project | 列项目（当前打标） | `/project 2` 或 `/project ledger` |
| /agent | 列 Agent（当前打标） | `/agent 2` 或 `/agent dev` |
| /convo | 进入会话模式 + 列已有对话（活跃打标） | `/convo 数据库选型` 直接绑定 |
| /list（convo） | 列最近对话 | — |
| /switch（convo） | 列对话（当前打标） | `/switch 2` |
| /oc | 进入 oc 模式 + 列实例（活动会话自动绑定） | `/oc main-exec` |
| /list（oc） | 列绑定实例的会话（当前打标） | — |
| /switch（oc） | 列会话 | `/switch 3` |
| /model | 列该实例可用模型（当前打标） | `/model 3` 或 `/model glm-5.3` |
| /agent（oc） | 列该实例可用 Agent（当前打标） | `/agent 2` |
| /stop | — | 中止当前实例执行 |
| /new | — | 新建（convo 对话 / oc 会话），自动绑定 |

全局命令仅：/help /status /exit /reset。模式内未知指令 → 回复当前模式可用命令清单（不猜意图）。

## 3. 卡片使用规则：只有三种时刻

| 用途 | 卡片 | 判断标准 |
|---|---|---|
| **要你点** | 审批（节点/命令/oc 权限/oc 提问）、监督提案、每日裁决、澄清表单、ask_user、讨论拍板 | 有按钮/输入框 = 卡片 |
| **跟着变** | 任务生命周期卡 | 一个活状态持续原地更新 = 卡片 |
| **要排版** | convo/oc 终稿卡（代码块/markdown 渲染，**无按钮**） | 纯文本渲染不了代码 = 卡片 |

其余一律纯文本：命令回复、列表、切换确认、受理回执、插话回执、错误提示。

## 4. oc 全局监控（rev2 新增）

**监控范围**：所有实例（managed + attached）的所有会话，不限于当前绑定。

| 事件 | 触发 | 推送 |
|---|---|---|
| 会话完成 | session idle（且本轮有活动） | 结果通知卡（实例/会话/用时/回复正文截断） |
| 待确认权限出现 | pendingPerms 新增 | 权限审批卡（批准/拒绝，answerPermission） |
| 待回答提问出现 | pendingQuestions 新增 | 提问卡（输入框作答，answerQuestion） |
| 执行失败/超时 | error / 30min 上限 | 失败通知文本 |

**实现机制**：
- 完成/失败：订阅 bus dashboard 频道 `oc_event`，过滤 idle/error 事件，按 `instance+session` 去重（同会话同轮只推一次）。
- 权限/提问：30s 周期扫描 manager 的 pending 聚合（对齐 clarifyTimeout 扫描器模式），与上次快照 diff → 新增推卡、已解决标记。
- **通知落点**：oc 模式激活时记录通知聊天（`feishu:oc:notify_chat`）；未激活时回落到 approvers 用户私聊（open_id 直发）。
- **噪音阀门**：config.feishu.oc_watch = `all`（默认，按你要求全面监控）/ `managed`（只监控托管实例——attached 桌面实例你在现场，不需要推送）/ `bound`（只监控绑定会话）。

## 6. 状态机

| 对象 | 状态流 |
|---|---|
| 私聊模式 | task ⇄ convo ⇄ oc 互斥；/exit→task；session 24h 过期回落 task |
| 任务卡 | queued→running→waiting_approval→success/failed/cancelled（原地更新） |
| ask_user / 提案 / 权限卡 | waiting→answered / rejected / expired（超时或已决议再点回"已处理"） |
| 澄清卡 | waiting→answered→再评估（clear/下一轮/3 轮封顶） |
| oc 监控 | 每会话每轮一次完成通知（idle 去重）；pending 卡按 id 幂等，解决即失效 |
| 推送去重 | 停靠位 1h 一卡；列表序号缓存随新列表覆盖 |

## 7. 全局交互规则（实现红线）

1. 按钮回调过 approvers 白名单 + journal 审计。
2. 结果卡必须 `{card:{type:'raw',data:…}}` 随响应帧返回（裸卡片被飞书回滚——v1 实测）。
3. 卡片不放内网链接；超长截断提示回面板。
4. 推送落点 = 绑定聊天；oc 全局监控有独立通知落点（激活聊天 → 回落 approvers 私聊）。
5. 噪音预算：progress/delta 不进飞书；oc 监控按 oc_watch 配置收敛。

## 8. 典型使用流

```
早上  /queue → 车道快照
     （推送）C3 命令审批卡 → 点批准 → 原地变绿
中午  @机器人 优化首页加载 → 建任务 → 任务卡演进到成功
下午  /oc → 自动绑定 main-exec → 发需求 → 回执"已发送，完成后推送" → 关飞书
     （推送）C10 main-exec 已完成 + 结果
     （推送）C11 桌面实例 TUI 出现权限确认 → 点批准
晚上  /convo → 列出对话 → /switch 1 → 讨论方案
     （推送）分歧拍板卡 → 点选择 → 继续讨论
     /exit → /metrics → 今日成本摘要
```
