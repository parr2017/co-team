# 公开仓库维护说明（双分支私有化流程）

> 本文档只存在于 private 分支，不会进入公开仓库。
> 背景：自进化 P0（自修改门禁 + 缺陷转化 + 质量度量）与两份设计/审计文档为私有内容，
> 公开仓库（github.com/parr2017/co-team）的 main 分支不包含它们。

## 分支模型

| 分支 | 内容 | 推送目标 |
|---|---|---|
| `main` | 公开代码（无任何自进化实现） | `origin`（公开仓库） |
| `private` | main + 自进化私有实现 + 私有文档 | 私有备份仓库（待建：`parr2017/co-team-private`） |

- `private-backup` 分支：私有化改造前的原始历史链（2026-09-06），仅作灾备，确认私有远端就绪后可删。
- 已配置 `remote.origin.push = refs/heads/main`：**origin 物理上只接受 main 推送**，
  `git push` / `git push origin` 都不可能把 private 推到公开仓库。

## 日常流程

1. **公共功能**：在 main 提交 → `git push`（只影响 main）→ 切到 private 执行 `git merge main`。
2. **私有功能**：只提交到 private，**永不** cherry-pick / merge 进 main。
3. **备份**：定期 `git push private-remote private`（私有远端建好后执行一次
   `git remote add private-remote git@github.com:parr2017/co-team-private.git`）。
4. **敏感自查**：在 main 上发布前，如改动触及 orchestrator/harness/deliverable/api 等文件，
   `git grep -lE "self_mod_gate|DefectReport|delivery_check|fix_for|summarizeQuality"` 应无结果。
