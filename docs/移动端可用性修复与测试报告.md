> 日期：2026-09-07

> 背景：用户反馈移动端在项目内下发任务无法完成——① agent 选择下拉空白；② 澄清阶段显示 "Fail Load" 且界面长时间无响应。要求修复后对移动端做全功能可用性测试，并向 co-team 项目下发一个评估任务。

## 一、问题定位与根因

### 问题 1：任务下达页"主 Agent 模型 / 所属项目"选择器空白（已修复，B 档前后端联动）

**根因**：`mobile/src/views/TaskCreateView.vue` 使用的是 **Vant 3 的多列数据格式 `[{ values: [...] }]`**。项目实际安装 Vant 4（4.10.2），其 `getColumnsType()` 只识别 `PickerOption[]` / 多维数组 / `children` 级联三种格式，旧格式被判定为"default"单列，其中唯一的元素 `{ values: [...] }` 没有 `text` 字段，渲染为一个**空白选项行**。同时 `@confirm` 回调仍按 Vant 3 的 `v[0]` 签名取值，即使能选中也取不到结果——两个选择器双双失效，任务下达流程无法正常操作。

**修复**（`TaskCreateView.vue`）：
- 列数据改为 Vant 4 对象选项 `{ text, value }`（项目选择器直接以 `value` 携带项目 id）；
- `@confirm` 改为 Vant 4 事件签名 `({ selectedOptions }) => ...`，从 `selectedOptions[0].value` 取值；
- `loadProjects()` / `loadModels()` 的失败重试由"每 2 秒无限重试"改为**最多 3 次**，失败后 cell 显示"加载失败 · 点击重试"供手动恢复。

### 问题 2：澄清阶段 "Fail Load" + 界面长时间无响应（已修复，B 档前后端联动）

**根因一（主因）——同步 LLM 请求超出手机端 HTTP 超时**：
- `POST /api/tasks`（创建）与 `POST /api/tasks/:id/clarify`（澄清）在请求线程内**同步等待 LLM**：需求评估单次 10~60s（`model_wait_timeout_sec` 默认 120s），需求清晰后的 `generateTaskGraph` 规划实测耗时 2~4 分钟（本项目 3 个模型：远程 glm-5.3-flash + 两台局域网 vLLM/LM Studio，慢时更久）。
- **手机 Safari/WebKit 对 fetch 有 ~60 秒硬超时**，超时抛 `TypeError: Load failed`——即用户看到的 **"Fail Load"**（Chrome 下为 "Failed to fetch"）。请求被浏览器杀死后，服务端仍在继续跑，但手机端只得到一个报错 toast，页面停在无内容的死状态，重新提交又从头再等——表现为"界面长时间无响应"。

**根因二（放大器）——ClarifyView 无错误恢复界面**：加载失败只弹一个 toast，页面没有重试入口、没有加载态，问题列表为空时整页只剩提交按钮。

**修复**：
- 服务端（`orchestrator.ts` + `api/index.ts`）新增 **`plan_async` 异步模式**（移动端默认启用）：
  - `POST /api/tasks` 带 `plan_async: true` 时：登记任务图（status `pending`）后**立即返回** `{status:'pending', task_id}`；需求评估与计划生成转入后台 `assessThenPlan()` / `planInBackground()`——评估不通过转 `clarifying` 并发出 `task_needs_clarification` 事件，通过则后台规划至 `planned`；
  - `POST /api/tasks/:taskId/clarify` 带 `plan_async: true` 时：记录回答后立即返回 `{'assessing'|'pending'}`，重新评估（`assessNextRound`）与规划（`planInBackground`）全部后台执行，下一轮问题通过 `task_needs_clarification` 事件送达（移动端澄清页本就从事件读取问题）；
  - 后台失败兜底：`failGraph()` 将任务置为 `failed` 并发出 `task_plan_failed` 事件（新事件类型），UI 永远不会无限等待；后台流程在关键节点检查 `isCancelled`，取消任务即刻生效；
  - **桌面端 web 不传 `plan_async`，完全走原同步路径，行为零变更**。
- 移动端（`TaskCreateView.vue` / `ClarifyView.vue` / `api/index.ts`）：
  - 提交后秒回，跳转任务详情页，由阶段条 + WS 实时事件 + 8 秒轮询兜底展示"团队评估需求中 → 澄清中 → 计划待确认"的流转；
  - `ClarifyView` 增加**加载态与可重试错误态**（"重新加载 / 查看任务详情"双按钮），不再出现死页面；
  - `request()` 对 `fetch` 网络异常统一映射为中文提示"网络连接失败或请求超时，请检查网络后重试"，`updateNode` 的裸 fetch 一并统一；
  - `TaskDetailView` 成员条为 `pending` 状态补充"团队评估需求中，请稍候…"提示；
  - `events.ts` 新增 `task_plan_failed` 事件的中文化映射；
  - `InterventionInput` 非 running 态提示文案区分"澄清中"与"已结束"。

## 五、二轮发现（用户下发任务 gnq6h5p6 触发）：成果回写缺陷

任务执行成功（7/7 节点、123.6k tok）后，用户反馈"没有得到任何结果"。排查发现两个问题：

1. **成果被沙箱吞掉（严重，已修复）**：docs agent 在沙箱（`coteam-sbx-*`）内写出最终报告 `report_dev_perspective.md`，任务结束时 `syncToWorkspace` 将沙箱回拷工作区，但该调用 **catch 后静默返回 false，orchestrator 也不检查返回值**——拷贝失败（Windows 文件锁等瞬时原因）后任务仍报 success，全部成果滞留沙箱。修复：
   - `orchestrator.ts` 成功路径检查 `syncToWorkspace` 返回值，失败即转 `failed` 并**落入既有的"已完成节点回收"路径**（reset → mergeAllNodes → 重同步 → 提交），回收再失败则明确标记 `sandbox_preserved` 留待人工；
   - `git.ts` syncToWorkspace 失败时输出错误原因日志；
   - `sandbox.ts` IGNORE 集合补充 `logs`、`.history`（运行时产物，同步无价值且易撞锁）。
2. **移动端聊天流断线不重拉（体验，已修复）**：`ChatStream` 仅在挂载时拉取一次 journals，之后纯依赖 WS 推送；WS 断线（手机网络常态）后页面永远显示"暂无对话记录"。修复：暴露 `useDashboard.onResync`，ChatStream 在 WS 重连（`connected` false→true）与回前台 resync 时自动重拉 journals。

文件已人工从沙箱抢救至工作区根目录：`report_dev_perspective.md`。

回归：35 个测试文件 / 197 用例全部通过；server tsc、mobile vue-tsc+vite build 均通过。

## 六、三轮修复（2026-09-08）：群组讨论底部遮挡 + 新建项目无法选择目录

**背景**：用户反馈移动端群组讨论两个问题——① 讨论详情页底部（@点名、输入框、继续讨论/生成方案/转项目操作行）被浏览器工具栏遮挡，无法操作；② 群组讨论"转项目"与项目页"新建项目"弹窗里工作区只能手输绝对路径，没法浏览选择目录（发起任务页明明有目录选择器）。

**根因与修复**：

1. **底部遮挡**：`DiscussionDetailView.vue` 容器 `.disc-detail` 使用 `height: 100vh`——全站唯一的例外。移动端浏览器的 `100vh` 按"地址栏收起"的大视口计算，地址栏展开时实际可视区更矮，超出的底部内容被浏览器 UI 压住且因 `overflow:hidden` 无法滚动。
   修复：改为 `height: 100%`（根容器 `#app` 本就是 `100dvh`，与其余页面统一），并给 `.input-zone` 与弹层 `.sheet` 增加 `env(safe-area-inset-bottom)` 底部安全区内边距。
2. **目录选择缺失**：目录级联选择弹层此前内联在 `TaskCreateView.vue` 里无法复用；web 端同样只有 `TaskForm` 有选择器，`DiscussionConvertDialog`（转项目）与 `ProjectView`（新建项目）都缺。
   修复：
   - 移动端提取共享组件 `mobile/src/components/DirPicker.vue`（`v-model:show` + `@pick`，弹出即加载根目录，样式并入组件），`TaskCreateView` 改用组件（删除内联实现，顺带清掉从未渲染的 breadcrumbs 死代码）；`DiscussionDetailView` 转项目弹窗与 `ProjectsView` 新建项目弹窗的"工作区"字段增加「选择」按钮接入选路器，保留手输能力（脚手架可创建新目录的场景仍需输入不存在的路径）。
   - Web 端提取共享组件 `web/src/components/DirPickerDialog.vue`（支持 `start-path` 定位到当前路径），`TaskForm` 改用组件，`DiscussionConvertDialog` 与 `ProjectView` 新建项目对话框的工作区字段加「选择目录」按钮，双端行为对齐。

**改动文件**：`mobile/src/components/DirPicker.vue`（新增）、`mobile/src/views/TaskCreateView.vue`、`mobile/src/views/DiscussionDetailView.vue`、`mobile/src/views/ProjectsView.vue`、`web/src/components/DirPickerDialog.vue`（新增）、`web/src/components/TaskForm.vue`、`web/src/components/DiscussionConvertDialog.vue`、`web/src/components/ProjectView.vue`。

**验证**：mobile `npm run build`（vue-tsc + vite）通过；web `npm run build` 与 `npx vue-tsc --noEmit` 通过（零报错）。无接口/服务端改动。
