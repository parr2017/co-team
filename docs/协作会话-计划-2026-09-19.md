# 协作会话功能 — 实施计划（2026-09-19）

## 一、功能定义

为每个项目创建 **1对1 长对话会话**：用户指定模型（可中途切换），agent 直接读写项目工作区、执行命令，过程流式上屏；agent 可自行 spawn 项目内现有 agent（dev/review/docs…）协同；多模态收发（图片/文件）。不占用 taskQueue 车道、不走 TaskGraph/DAG 规划。对标 OpenCode / Codex / ZCode 的交互模式。

## 二、已确认决策

| 决策点 | 结论 |
|---|---|
| 改动落点 | 直接改项目工作区 + 会话首 turn 自动快照可回滚 |
| 项目互斥 | 允许与任务/其他会话并行（diff 可见，风险自担） |
| 模型失败 | 自动走 ModelPool 降级链 + 显著降级提示卡片，pin 不变 |
| 主 agent | 新人设 `agents/partner/`（显示名「搭档」），可 spawn 项目内现有 agent 协同（≤12轮/≤3并发） |
| 多模态 | 一步到位：原生 image parts（vision 模型）+ 自动回退 vision.ts 富化；multipart 文件上传 ≤20MB；share_file 反馈卡 |
| 插话 | 默认**排队**（多队列消息合并为一条，codex 式），可切换**打断**（kill 进程树 + 半截回复标记 `[已打断]`，待审批命令连带拒绝） |
| 命名 | 功能「协作会话」，主 agent 人设「搭档」（目录 `agents/partner/`），双端菜单/tab「协作」，路由 slug 保持 `/convo` |
| 图标 | Web 用 Element Plus 官方图标（@element-plus/icons-vue），mobile 用 Vant 自带 van-icon，零新增依赖；UI 禁用 emoji 图标 |

## 三、架构

```
web/mobile 新页面 ──REST+WS──▶ /api/convos/* ──▶ server/src/convo.ts（新引擎）
   ├─ llm.chatStreamed（流式 + watchdog 复用）
   ├─ ModelPool（pin 指定模型 + 降级链 + 降级提示）
   ├─ tools.applyToolCalls（全部现有工具 + MCP）
   ├─ sandbox 权限/目录监狱/commandGuard（与任务系统一致）
   ├─ skills 索引注入 + load_skill；askGate 阻塞问答
   ├─ media.ts 图片 + 新增文件上传；snapshot.ts 快照回滚
   └─ spawn_agent 子 agent 工具循环
```

参照：`discussion.ts` 群聊引擎（LLM直调+工具直执+监狱+流式）为 80% 雏形；`callAgent`（orchestrator.ts:3062）为多轮工具循环参照；`foldMessagesInto`（orchestrator.ts:182）抽取共享。

## 四、后端设计

### 4.1 存储（Redis KV）
- `convo:<id>` 元数据 `{id, project_id, workspace, title, agent_id, model_id, status, snapshot_id, created_at, updated_at}`
- `convo:<id>:msgs` list（上限 2000）`{id, role, kind: text|tool|image|file|notice|degrade|approval|ask|interrupt, text, meta, ts, model}`
- `convo:<id>:pending` 排队消息队列；`convo:<id>:approvals` 待审批命令
- `convo:project:<pid>` 会话索引；上下文 = 静态前缀 + append-only，超线折叠（`fold.ts`）
- WS 事件（复用 dashboard 频道）：`convo_status / convo_delta(1s节流) / convo_tool / convo_message / convo_queued / convo_interrupted / convo_degrade / convo_approval`

### 4.2 引擎 `server/src/convo.ts`
- `runTurn`：system（搭档人设 + skills 索引 + mcpBlock + 工作区树）→ chatStreamed → tool_calls → applyToolCalls → 结果追加 → 循环至无工具调用（≤30 轮可配）
- 每会话同时仅一个 turn；AbortController 可随时停止；打断时 kill 运行中子进程树
- `waiting_approval` / `waiting_ask` 挂起；turn 间检查 pending 队列

### 4.3 模型指定与降级
- 会话级 PATCH `model_id` + 每条消息可覆盖；失败走 fallbackChain，插入 `degrade` 卡片（"⚠ 主模型 X 不可用（原因），本轮已用 Y [改回]"），pin 不变

### 4.4 子 agent（`spawn_agent` 工具）
- `{agent, task}` → 独立小循环（该 agent prompt+绑定技能+MCP 白名单，≤12 轮，≤3 并发），活动嵌套卡直播，摘要回注主循环；权限继承会话策略

### 4.5 多模态
- 图片：pinned 模型带 image tag → 原生 image parts（llm.ts 支持 content 数组）；否则回退 vision.ts 富化
- 文件：`POST /api/convos/:id/files`（multipart ≤20MB）→ `data/media/files/` + `<ws>/.coteam/user-files/`
- 反馈：`share_file {path}` → file 卡片；`GET /api/convos/:id/file?path=`（监狱校验）预览/下载

### 4.6 安全网
- 首 turn 前 createSnapshot；UI 一键回滚；每轮 `git diff` → `GET /api/convos/:id/diff` → diff 卡
- `approve_required`：park 会话级 pending → 审批卡（批准一次/拒绝/"总是允许"P1）；打断连带拒绝

### 4.7 API
```
GET/POST /api/convos                  GET /api/convos/:id/messages?after=
POST /api/convos/:id/messages         {text, images[], files[], model_id?, mode: queue|interrupt}
PATCH/DELETE /api/convos/:id          POST /api/convos/:id/stop   POST /api/convos/:id/files
GET /api/convos/:id/file|diff         POST /api/convos/:id/rollback
POST /api/convos/:id/approvals/:cid   POST /api/convos/:id/asks/:aid
```

## 五、前端（web + mobile 双端同步）

- web：第 6 路由 `/convo`（router.ts + App.vue PassThrough 分支）。左会话列表（项目分组）+ 右聊天流（复用 ChatStream 布局：工具折叠卡/diff/degrade/approval/ask/file 卡、图片九宫格、打字指示器）+ 输入栏（排队/打断 toggle、📎图片/文件、@引用、模型选择器、发送/停止）

- 双端 `utils/events.ts` 新增 `convo_*` 中文映射；mobile api 镜像
