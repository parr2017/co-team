## 人话摘要

- **解决什么问题**：learn-english 任务反复"假完成"跑不下去。查明主凶不是模型谎报，而是基础设施：任务的沙箱（给 agent 干活的独立工作目录）创建失败时**静默**降级成一个没有 git 的临时拷贝目录——产物无处提交，服务一重启就全部失联，"已完成"节点变成谎言，任务最终被停到人工。
- **做什么**：修沙箱创建的容错与降级可见性、给降级模式补持久化能力、重启后自动抢救成果、开发期重启不再误停任务、修补假完成守卫的四个已知缺口、验收口径收紧为严格缺省。
- **怎么做**：改 server 侧 7 个文件（sandbox/orchestrator/index/config/types + 测试），分 6 个阶段 16 步，每步独立可验证、独立提交。
- **做完后效果**：同样的重启风暴下，任务成果不再丢失、不再被误 park；沙箱降级会大声报警且产物可恢复；谎报/漏报的"假完成"会被修复轮拦下；测试不过的任务不再算成功。

## 2. 现状与约束

**执行期重大修正（2026-09-27 晚，以调试实证为准）**：原判"rmSync 异常从 catch 回调炸出"只是潜在隐患（真实存在但未触发）；**真正根因是清扫循环的路径前缀匹配**——git 输出正斜杠路径、`worktreeRoot()` 返回反斜杠路径，`startsWith` 在 Windows 上**永远失败** → 遗留 worktree 从未被清扫（pk0udn4p 的 worktree 至今在就是铁证）→ `coteam/base` 被占住 → `branch -f` 必炸 → 该仓库每一次沙箱创建都静默降级 Temp。已修复为归一化后匹配。

**事实（附证据）**：

- 沙箱清扫循环的路径匹配在 Windows 上永远失败（`sandbox.ts:163`，git 正斜杠 vs `worktreeRoot()` 反斜杠）——遗留 worktree 从未被清扫，`coteam/base` 被占住，每次 `createWorktreeSandbox` 都在 `branch -f coteam/base` 炸掉（调试实证：`fatal: cannot force update the branch 'coteam/base' used by worktree at ...`）。
- 隐患（同区域）：`worktree remove --force` 失败后 `fs.rmSync` 兜底无 try/catch，异常会炸掉整个创建；且**锁定的 worktree（worktree lock）连 prune 都不清理**——目录删了注册仍在，必须先 `worktree unlock`。
- Temp 拷贝沙箱**不含 .git**：IGNORE 集合含 `.git`（`sandbox.ts:90`），`cpSync` 过滤后是非 git 目录 → `createNodeBranch`/`commitAllOnBranch` 全部静默失败，节点产物只存在于本次 run 的 Temp 目录。
- 物证：us55tbhs 节点产物只在 `Temp\coteam-sbx-u0siiD`（含 X-Ai-Cache 版 ai_service.dart）与 `coteam-sbx-e3O22k`（含 AiStatsPanel），工作区 `D:\pxx\projects\learn-english` 无这些改动。
- 降级回退只打 `console.error`（`sandbox.ts:121`），不进结构化日志，今天日志零痕迹。
- park 阈值硬编码：`retries > 3`（`orchestrator.ts:462`）；优雅退出处理器已存在（`index.ts:419-425`，目前只 closeBus+exit）。
- 任务收尾失败路径已有 partial-recovery 逻辑（`orchestrator.ts:1295-1345`），但重启场景走不到它；节点 diff 已有持久化存档 `saveNodeDiff`（`store.ts:368`）。
- **续跑场景的抢救不能走 gitCommit**：gitCommit 提交后回切用户原分支，工作树文件被抹掉；而续跑基线舞步只认工作树脏改动，恢复提交反而会被 `branch -D` 清掉（调试实证）→ 抢救成果必须保留为工作区未提交改动。
- 守卫缺口：实际写盘未申报（unreported）不参与裁决；`no_changes_reason` 豁免无一致性校验（`:2225-2264`）；light 档（沙箱=工作区）无 phantom+内容级守卫（`:2088`、`:2429-2433` 的前提是 `sandbox !== workspace`）。
- **守卫偏差（执行期评估）**：闸内幻影修复轮（原步骤 11）与收尾守卫 applyPhantomGuard 的既有语义冲突——部分幻影剔除放行是 jgfhfaux 复盘的深思熟虑决策（phantomGuard.test 锁定），且最终 JSON 的 `files[]` 由 applyFinalOutput 闸后落盘，闸内存在性检查必误判。撤回闸内幻影检查，幻影拦截维持收尾最后防线。
- 验收软门：`acceptance_policy` 原缺省 tolerant（`orchestrator.ts:1356,1378`），本次改为缺省 strict（可配置回 tolerant）。

**约束**：
- 不动 learn-english 三个任务的状态与其仓库（只读梳理）。
- AGENTS.md：orchestrator 核心改动须全量测试+三端构建；本次无 web/mobile UI 改动（notify 复用现有事件类型，无新卡片——评估结论：双端无需同步）。
- 提交：中文 conventional commit；默认在当前分支 `devoc` 提交推送。

## 3. 方案与取舍

| 方案 | 做法 | 优点 | 代价/风险 |

## 6. 风险与回滚

| 风险 | 概率/影响 | 预防 | 翻车了怎么办 |
